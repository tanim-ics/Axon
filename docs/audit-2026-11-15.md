## Summary

Axon is in good structural health. The security rules the project sets for itself hold: there is no
`innerHTML`, `eval` or inline style anywhere in the JavaScript, the Content Security Policy matches what the
page loads, and every read from `localStorage` passes through a sanitiser. The spaced-review logic matches
its specification, and all 59 tests pass.

The audit found **62 findings: 0 critical, 2 high, 19 medium, 41 low.**

| Area | High | Medium | Low | Total |
|---|---|---|---|---|
| 1. Content quality | 0 | 5 | 5 | 10 |
| 2. Engine correctness | 0 | 2 | 7 | 9 |
| 3. UI/UX | 0 | 6 | 10 | 16 |
| 4. Design and CSS | 2 | 3 | 12 | 17 |
| 5. Security and architecture | 0 | 0 | 5 | 5 |
| 6. Test coverage | 0 | 3 | 2 | 5 |
| **Total** | **2** | **19** | **41** | **62** |

The two high findings are both in the stylesheet and both cheap to correct:

1. The class `.mrow` is defined twice, so Field mission rows take the styling written for the mastery map
   (D-1).
2. The secondary text colour `--muted` is below the WCAG AA contrast ratio on every surface it is used on
   (D-2).

The largest piece of remaining work is in the question bank: every question has two wrong options and every
concept has two questions, which makes a Master level passable by guessing about one time in five (C-1, C-2).

## Scope and method

**Files in scope:** `index.html`, `css/styles.css`, `js/content.js`, `js/engine.js`, `js/ui.js`, `js/app.js`,
`js/markdown.js`, all 16 files in `js/games/`, and `tests/engine.test.js`.

| Method | Applied to |
|---|---|
| Read in full, line by line | `index.html`, `styles.css`, `engine.js`, `ui.js`, `app.js`, `markdown.js`, all 16 game files |
| Profiled by script | `content.js`: the 332 bank questions, the 50 boss decisions, level titles |
| Test names read, selected tests read in full | `tests/engine.test.js` (streak, review hardening, profiles) |
| Test suite run | `npm test`: 59 passed, 0 failed |
| Computed in a script | Contrast ratios (WCAG 2 relative luminance) for the colour tokens |
| Checked in a browser | Findings marked ✔: computed style and page width at 320px and 375px |
| Pattern search | Banned DOM calls, `localStorage` use, timers outside `api.later` |

### Limits of this audit

- `content.js` was **not** read line by line. The content findings come from heuristics (option length,
  length of the "why", word overlap between the answer and the "why", stem patterns). They point at where to
  look. They are not a judgement of each question.
- **No level was played.** Finding D-1 is confirmed by computed style, not by looking at a mission on screen.
- Line lengths at desktop width are **estimated** from the character width measured at 375px, because the
  preview pane was 375px wide.
- Contrast ratios are computed from the token values. Text on translucent tints was blended over the surface
  it sits on; real rendering can differ slightly.
- Accessibility was reviewed from the code. No screen reader was used.

### Severity scale

| Severity | Meaning |
|---|---|
| Critical | Data loss, a security hole, or the app cannot be used |
| High | A visible defect or accessibility failure that affects most users |
| Medium | A defect that affects some users or some screens, or weakens what is learned |
| Low | A minor defect, an inconsistency, or a hardening opportunity |

Each finding gives the file, the line or function, the severity, the finding in one sentence and the fix in
one sentence. The fix line names the direction only. No fix has been designed or applied.

## 2. Engine correctness (`js/engine.js`)

The spacing rules match the specification: a right answer when due waits 1, 3, 7, then 21 days; a wrong
answer at any time resets to box 0 and tomorrow; a right answer before the due day changes nothing. The file
has no DOM, storage or clock access.

| ID | File · line | Severity | Finding | Fix |
|---|---|---|---|---|
| E-1 | `engine.js` · `sanitizeState` (195), `recordReview` | medium | A valid but far-future `due` date (a clock set forward and back, or edited storage such as `9999-12-31`) is kept, so that idea never comes due again. | Cap `due` at a fixed distance from a `today` passed in. |
| E-2 | `engine.js` · `touchStreak` (286) | medium | If today is earlier than `streak.last` (a corrected clock, or travel west across the date line), the gap is negative and the streak resets to 1. | Treat a negative gap as the same day. |
| E-3 | `engine.js` · `recordReview` (358) | low | An answer is recorded for a concept whose level is not finished, so the concept skips the "new" status and can be at box 1 before the level is cleared. | Record only for learned concepts, or document the exception. |
| E-4 | `engine.js` · `awardLevel` (312) | low | It rebuilds the state field by field, while `recordReview`, `touchSession` and `recordBlitz` copy every key; a future persisted field would be dropped each time a level is finished. | Copy all keys the same way in all four functions. |
| E-5 | `engine.js` · `profileKey` (101) | low | An invalid id returns the main profile's storage key; only the caller's own check stops a delete from removing the main profile's progress. | Return null for an invalid id and have callers handle it. |
| E-6 | `engine.js` · `addProfile` (122) | low | When the highest-numbered profile is deleted its id is reused, and an id above `p9999` fails the id pattern and disappears on the next load. | Keep a counter that never goes back, and refuse at the limit. |
| E-7 | `engine.js` · `cleanName` (87), `profileName` (96) | low | Every non-ASCII letter is stripped, so "Jörg" is saved as "Jrg" and a name in another script becomes "Player". | Allow Unicode letters and digits. |
| E-8 | `engine.js` · `defaultState`, `sanitizeState` | low | The version field `v: 1` is written but never read, so there is no migration path for the day level ids change. | Read `v` and branch on it before a renumbering is needed. |
| E-9 | `engine.js` · `buildQuestions`, `shuffle`, `fixOptions` | low | These default to `Math.random` when no `rng` is passed, the only departure from pure functions in the file. | Make `rng` required, or accept the default as documented. |

### What the brief asked for, item by item

- **Drift from the spacing specification:** none in the intervals. E-1 and E-3 are the two places where the
  stored schedule can differ from what the specification implies.
- **Unhandled edge cases:** clock skew (E-1, E-2). Corrupted storage is handled: unparseable JSON falls back
  to a default state, and partial corruption is repaired field by field.
- **Sanitisation gaps:** E-1 (the date is checked for validity but not for range) and E-7 (over-strict, not
  unsafe).
- **Pure-function violations:** E-9 only.

### What the brief asked for, item by item

| Location | Key | Sanitiser |
